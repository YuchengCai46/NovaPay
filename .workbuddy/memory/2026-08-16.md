## 关键 DEBUG：前端静态资源 404（致命）
- 现象：浏览器打开后无样式/无 JS/无图标（整页空白或裸文本），但 API 全部正常（pytest 22 通过、登录/账户接口 200）。`/js/*`、`/css/*` 全部 404。
- 根因 1：`app/__init__.py` 原 `Flask(__name__, static_folder="frontend", static_url_path="")` 中 `static_folder` 是相对路径，Flask 会相对 app 包目录解析成 `NovaPay/app/frontend`（不存在），而真实前端在 `NovaPay/frontend`；且原代码没有 `/js`、`/css` 的显式路由（只有 `/` 和 `/admin` 走 send_from_directory）。
- 修复：改为 `static_folder=None` 关闭内置 static，新增显式路由：
  - `@app.route("/js/<path:filename>")` → `send_from_directory(os.path.join(frontend_dir,"js"), filename)`
  - `@app.route("/css/<path:filename>")` → `send_from_directory(os.path.join(frontend_dir,"css"), filename)`
  - 注意：`/js/<path:filename>` 的 `filename` 不含 `js/` 前缀，必须拼接子目录，否则 send_from_directory(frontend_dir, "icons.js") 会找不到文件而 404。
- 根因 2（沙箱坑）：改完 .py 后仍 404 —— 沙箱时钟漂移导致旧的 `__pycache__/*.pyc` mtime 比 .py 新，Python 跳过重编译，运行的是旧代码。必须 `find . -name __pycache__ -exec rm -rf {} +` 后重启。
- 根因 3（进程清理）：Git Bash 的 `pkill`/`taskkill` 杀不掉 Windows 侧残留 python 进程（多实例占用 5000 端口，netstat 可见多个 LISTENING PID）。必须用 **PowerShell 工具** `Stop-Process -Id <pid> -Force` 才能清掉，或直接换端口。
- 验证：`curl /js/icons.js` 返回 200 + `text/javascript` 且含 `NETLOGOS`；`/css/style.css` 含 `aurora`；`node --check` 两个 JS 通过；pytest 22 通过。
- **用户操作坑**：直接双击 `frontend/index.html`（file:// 协议）打开会白底黑字、点不动——因为页面用绝对路径 `/css/style.css`、`/js/app.js`，file:// 下解析到文件系统根导致资源 404。必须经由服务器 `http://127.0.0.1:5000/` 访问。已新增 `start_novapay.bat`（关占用端口→venv 启动 Flask→打开浏览器）作为一键启动。bootstrap() 即使未登录也会 renderAuth() 渲染登录页，故首屏即为可点击的登录/开户界面。
